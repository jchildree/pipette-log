Pipette Log

Digitized pipette calibration/verification log -- project summary & architectural decisions. Last updated 2026-07-22.

What this is

Replaces the paper pipette-verification form (basic_digital pipette log.pptx) with an iPad app used at the bench. A tech selects a balance and pipette, records Volume/Mass readings, the app determines Pass/Fail where a rule exists, and the tech signs off with a PIN.

Source form fields: Date/Initials · Verification Type (±3% Tolerance / Manufacturer specifications / After External Calibration) · Balance Number · Pipette Number · Pipette Range (µL) · Volume (µL) · Mass (mg) · Pass Y/N · Notes.

Confirmed decisions

Client platformNative iPad app (Swift/SwiftUI) -- ADR-001
ConnectivitySync defaults to live over REST; local cache + queued sync is the offline fallback, auto-drains on reconnect -- ADR-002
BackendNew Nexus app (Express REST API + MSSQL, on-prem), reuses @il/db / @il/auth -- ADR-003
Identity & sign-offNexus LDAP session + 6-digit PIN per entry -- ADR-004
Record integrityRegulated-lite (not full 21 CFR Part 11); signed entries immutable; corrections are appended, not edited -- ADR-005
Verification types3 mutually exclusive types; only ±3% Tolerance auto-calculates Pass/Fail in v1, other two are manual with a required note -- ADR-006

Open questions (flagged in ADRs, not yet decided)

  • How stale cached reference data is surfaced to the tech during an outage -- ADR-002
  • Whether balance/pipette reference data is owned by Pipette Log's own DB or pulled from an existing Nexus app (asset-manager, instrument-status) -- ADR-003
  • Where/how PINs are set and reset, and whether re-entry is required per-entry or per-session -- ADR-004
  • Whether unsigned draft entries are mutable before sign-off (current assumption: yes) -- ADR-005
  • Exact ±3% tolerance formula (Mass→Volume conversion) -- must come from the source SOP, not guessed -- ADR-006
